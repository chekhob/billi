# Plan: Commit Table Updates (Requirements + Updates)

Implement the Iceberg REST commit-table flow. Split into parts, starting with the `requirements` discriminator, then the `updates` discriminator.

**Stack:** Java 21, Quarkus 3.30.6, Jackson (`@JsonTypeInfo`/`@JsonSubTypes`), global `KEBAB_CASE` naming strategy.

**Reference spec:** `spec/rest-catalog-open-api.yaml`

---

## Part 1: `TableRequirement` DTOs — `assert-table-uuid` + `assert-ref-snapshot-id`

### 1.1 DTO changes

- **Rename** `src/main/java/org/acme/dto/TableRequirment.java` → `TableRequirement.java` (fixes the `Requirment` typo).
- **Convert** `TableRequirement` to a `public interface` with polymorphic annotations:

```java
@JsonTypeInfo(use = JsonTypeInfo.Id.NAME, property = "type")
@JsonSubTypes({
    @JsonSubTypes.Type(value = AssertTableUUID.class, name = "assert-table-uuid"),
    @JsonSubTypes.Type(value = AssertRefSnapshotId.class, name = "assert-ref-snapshot-id")
})
public interface TableRequirement {}
```

- **New record** `AssertTableUUID` — `@JsonTypeName("assert-table-uuid")`, field `String uuid`.
- **New record** `AssertRefSnapshotId` — `@JsonTypeName("assert-ref-snapshot-id")`, fields `String ref`, `Long snapshotId` (boxed — nullable per spec; `null` asserts the ref does not exist).

Note: KEBAB_CASE handles `snapshotId` ↔ `snapshot-id` automatically. No `@JsonProperty` needed.

- **Modify** `CommitTableRequest`:
  - `private List<TableRequirement> requirements;` (was singular `TableRequirment`)
  - Keep `TableUpdate updates` as stub for now
  - Add private fields + getters/setters + no-args constructor (match existing DTO convention).

### 1.2 Validation logic in `TablesServices`

New method `validateRequirements(...)`:

- Load the current table metadata from S3 (latest `.metadata.json`).
- For each requirement, use Java 21 pattern-matching switch:
  - `AssertTableUUID(uuid)` → compare against `IcebergMetadata.getTableUuid()`.
  - `AssertRefSnapshotId(ref, snapshotId)` → `ref` refers to `current-snapshot-id`, or in some cases a `snapshot-id` from the snapshots list (snapshots may not be modeled yet — separate issue). Compare accordingly.
- Return failure list or throw on first mismatch.

### 1.3 Post-validation: commit orchestration

New method `processCommit(NamespaceObject ns, String tableName, CommitTableRequest request)`:

1. **Load current metadata** — download latest metadata JSON from S3 (`MetadataRequests.downloadFile()`).
2. **Validate requirements** — call `validateRequirements()`.
3. **On validation failure** → return error response (409 Conflict / 400).
4. **On validation success** → return 200 OK for now; full update processing comes with `TableUpdate` work.

### 1.4 Wire `TablesResource.updateTable()`

```java
return tablesServices.processCommit(ns_object, table, commitTableRequest);
```

### 1.5 Tests

New `src/test/java/org/acme/CommitTableTest.java` (`@QuarkusTest` + REST Assured):

1. **Unit: Jackson round-trip** — inject `ObjectMapper`, serialize/deserialize a `CommitTableRequest` with both requirement types, assert correct record types.
2. **Integration: valid POST** — POST `/{tb_name}` with valid requirements body, assert 200.
3. **Integration: bad UUID** — wrong UUID, assert 4xx.
4. **Integration: bad ref snapshot-id** — wrong snapshot-id for a ref, assert 4xx.

## Part 3+: `TableUpdate` (25 variants) — family-grouped appliers

Discriminator property is `action` instead of `type`. There are 25 update actions per the spec.

### 3.1 Structure: family-grouped appliers (composition, not inheritance)

Keep `TablesServices` lean by delegating update application to dedicated applier beans via a dispatcher. One applier per *family* (~9 appliers), each owning a coherent slice of table state.

**`TableUpdateApplier` interface:**
```java
public interface TableUpdateApplier {
  Set<String> actions();                              // JSON action names this applier owns
  void apply(IcebergMetadata metadata, TableUpdate update);
}
```

**`TableUpdateDispatcher`** — ties appliers together via CDI auto-collection:
```java
@ApplicationScoped
public class TableUpdateDispatcher {
  private final Map<String, TableUpdateApplier> appliers;

  @Inject TableUpdateDispatcher(Instance<TableUpdateApplier> all) {
    // build Map<action, applier> from every TableUpdateApplier bean
  }

  public void applyAll(IcebergMetadata metadata, List<TableUpdate> updates) {
    for (TableUpdate u : updates) appliers.get(u.action()).apply(metadata, u);
  }
}
```

**Family applier example:**
```java
@ApplicationScoped
public class SnapshotApplier implements TableUpdateApplier {
  public Set<String> actions() { return Set.of("add-snapshot", "set-snapshot-ref",
                                               "remove-snapshot-ref", "remove-snapshots"); }
  public void apply(IcebergMetadata m, TableUpdate u) {
    switch (u) {
      case UpdateAddSnapshot(var s) -> m.addSnapshot(s);
      case UpdateSetSnapshotRef(var ref, var id, var type) -> m.setSnapshotRef(ref, id, type);
      ...
    }
  }
}
```

**Keying:** keyed by `action` string (not class), so `TableUpdate` gains an `action()` method; each record returns its `@JsonTypeName` value.

**Families:**
| Family | Applier | Actions |
|---|---|---|
| Snapshot | `SnapshotApplier` | add-snapshot, set-snapshot-ref, remove-snapshot-ref, remove-snapshots |
| Schema | `SchemaApplier` | add-schema, set-current-schema, remove-schemas |
| Partition spec | `PartitionSpecApplier` | add-spec, set-default-spec, remove-partition-specs |
| Sort order | `SortOrderApplier` | add-sort-order, set-default-sort-order |
| Format & identity | `FormatApplier` | assign-uuid, upgrade-format-version, set-location |
| Properties | `PropertiesApplier` | set-properties, remove-properties |
| Statistics | `StatisticsApplier` | set/remove-statistics, set/remove-partition-statistics |
| Encryption | `EncryptionApplier` | add/remove-encryption-key |
| View | `ViewApplier` | add-view-version, set-current-view-version |

### 3.2 Mutation lives on `IcebergMetadata`

Family appliers stay thin switches; state-change logic goes on the model as methods (`addSnapshot`, `setSnapshotRef`, ...). Model prerequisites (currently absent): `snapshots`, `refs`, `snapshotLog`, `schemas[]`, `partitionSpecs[]`, `sortOrders[]`, plus `Snapshot` / `SnapshotReference` / `SnapshotLogEntry` records.
